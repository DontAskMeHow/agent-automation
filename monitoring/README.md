# Каталог проблем автоматов

Записки об операционных проблемах от автоматических механизмов воркспейса (демо-задача `periodic.py`, периодический сборщик, чекер; далее — и другие). Агент читает каталог **только по запросу пользователя** (через `health.py problems`) или при подозрении на поломку.

## Записка

Одна проблема = один JSON-файл `<ISO-ts>_<source>.json` в этом каталоге. Поля:

| Поле | Что |
| --- | --- |
| `ts, updated_ts` | когда создана / последний раз тронута |
| `source` | механизм-автор: `demo`, `collector`, `checker`, … |
| `severity` | `error` / `warning` / `info` |
| `title, detail` | суть проблемы; `detail` при повторах дополняется через `--` |
| `status` | `new` → `reported` → `resolved` |
| `count` | сколько раз поднята (дедуп по `source`+`title` незакрытой) |
| `reported_ts` | когда агент сообщил пользователю |
| `resolved_ts, resolved_by, note` | кто/когда закрыл (mechanism/agent/user) и чем |

**Статусы:** `new` — никто не читал (агент при health-чеке сообщает в чат и переводит в `reported`); `reported` — в чат сообщено, не решено (показывается строкой «нерешённое ранее»); `resolved` — снято, **не читается**.

## Кто пишет и закрывает

- Механизмы: `problems.add(...)` в ветках сбоев; при само-выздоровлении (следующий успешный проход той же задачи) — `problems.close(..., by="mechanism", note="само-вылечилось")`. Дедуп внутри `add`: открытая записка с тем же `source`+`title` не дублируется — растёт `count`.
- Агент: по запросу читает `list_open()`, сообщает `new` и переводит в `reported`; чинит/снимает → `close(by="agent")`.
- Пользователь: сказал «закрыть» → агент вызывает `close(by="user")`.

## Инструменты

- `problems.py add|list|report|close` — CLI для ручного разбора (`--help` для подробностей).
- Импорт из скриптов: `sys.path.insert(0, str(Path(<workspace>) / "monitoring"))` → `import problems`.
- Записки (`*.json`) живут вне git (см. `.gitignore`); `problems.py` и этот README — в git.
